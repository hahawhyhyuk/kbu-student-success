# KBU AI 학생성공 레이더

출석·과제·LMS·성적·전공적응·진로 데이터를 함께 살펴 학업위험을 조기에 발견하고, 교직원이 적절한 학생지원을 검토할 수 있도록 돕는 Streamlit 프로토타입입니다.

현재 저장소의 학생 데이터는 모두 고정 시드로 생성한 가상데이터입니다. 위험등급은 학생을 처벌하거나 행정적 불이익을 주기 위한 판정이 아니라 지원 우선순위를 정하기 위한 참고정보이며, 최종 개입은 교직원이 검토합니다.

2026년 AI해커톤 대회 출품팀은 **Kare Bridge U**이며 소속은 경복대학교 디지털정보처 IR센터입니다.

> 경복대학교 학생의 위험 신호를 조기에 발견하고, AI 기반 맞춤 지원과 학습경로로 학생 성공을 연결하는 징검다리.

## 설치

Python 3.10 이상을 권장합니다.

```bash
cd kbu-student-success
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 실행

가상데이터를 다시 생성한 뒤 앱을 실행합니다.

```bash
python -m src.data_generator
streamlit run app.py
```

앱을 처음 열면 시연용 계정 확인 화면이 표시됩니다. synthetic 학생 ID(예: `S0003`)로 시작하면 `나의 체크인`·`마이페이지`·학생 `이용 매뉴얼`만, 교직원 데모 ID `STAFF001`로 시작하면 전체 대시보드와 교직원 검토·교육과정·관리자 화면 및 교직원 `이용 매뉴얼`만 라우터에 등록됩니다. 학생 계정에서는 다른 학생 선택기를 표시하지 않고 로그인한 자기 데이터로 범위를 고정합니다. 역할에 허용되지 않은 페이지는 상대 역할의 매뉴얼을 포함해 직접 URL로도 열리지 않습니다. 로그아웃하면 브라우저 session state를 비워 역할 간 데이터가 남지 않게 합니다. 사이드바의 모든 메뉴 그룹은 접을 수 있으며, 서비스 소개·시연 준비·발표 요약·초기경보 모델 검증은 기본적으로 닫힌 `관리자` 그룹에 배치됩니다. CSV가 없으면 동일한 고정 시드로 데이터를 자동 생성합니다.

현재 계정 확인은 실제 개인정보나 비밀번호를 사용하지 않는 해커톤 시연용입니다. 운영 환경에서는 ID 접두사 판별이 아니라 대학 SSO와 서버가 검증한 역할·학생 범위로 교체해야 합니다.

`발표 요약` 화면은 대회 포스터의 공식 심사기준인 공통 심사 80점과 주제 01 심사 20점을 현재 구현 근거 및 남은 검증 과제와 함께 정리합니다. 표시된 내용은 자체 예상점수가 아닙니다.

`초기경보 모델 검증` 화면은 synthetic archetype을 참조 라벨로 변환해 지원 신호 포착률, 정상 패턴 보존율, 단일 위험유형 일치율과 복합 패턴 고위험 포착률을 확인합니다. 같은 화면의 접힌 `Kare 대화 품질 회귀 검증`에서는 5개 학과·15개 synthetic 대화로 의미 상태, 한 문장 다중 추출, 과잉 추론, 척도 질문, 반복 주제와 확인 화면 전환을 점검합니다. 기본 결과는 Mock fallback과 서비스 안전장치의 재현성 기준선이며 실제 Gemini 정확도가 아닙니다. Gemini 확인은 사용자가 고른 사례 한 건에 대해서만 명시적으로 실행합니다.

Gemini API key는 선택사항입니다. 키가 없거나 호출에 실패해도 Mock provider로 전체 기능이 실행됩니다.

```bash
export GEMINI_API_KEY="your_api_key"
streamlit run app.py
```

Streamlit secrets를 사용할 경우 `.streamlit/secrets.toml`에 다음과 같이 설정합니다. 이 파일은 `.gitignore`에 포함되어 있습니다.

```toml
GEMINI_API_KEY = "your_api_key"
```

## 테스트

```bash
pytest
```

테스트는 역할별 페이지 allowlist·계정 검증·학생 자기 데이터 범위·로그아웃 상태 삭제, 시연용 교내 알림 중복 방지·상태 전이·체크인 연결, 위험점수 범위, 결측값 처리, 가상데이터 재현성·민감정보 미사용, Repository 계약, 실제 master 허용 열·중복·결측 검증, 2026년 1·2학기 전 학과 개설강좌의 개인정보 열 차단·분반 통합·교과 master 연결, 검토 완료 master의 백업·원자적 활성화·synthetic fallback, Kare 구조화 페르소나·Few-shot Schema·허용 Context와 15개 synthetic 대화 품질 기준선, 자유대화의 맥락 이해·반복 질문 방지·척도 질문 차단·Gemini 장애 fallback·비동의 직접 입력·제출 전 확인, 지원계획·개입 후 변화, DB 한정 프로그램·교과목 추천, 학습경로 군집·개발 후보와 학생·교직원 역할별 이용 매뉴얼을 확인합니다.

## 현재 구현 범위

- archetype 분포를 먼저 정한 가상학생 200명과 유형별 시연 대표 사례 8명
- `config/app_config.yaml`에 고정한 친환경건축과·유아교육과·실용음악과(3년제)·간호학과·소프트웨어융합과 5개 적용 학과
- synthetic 학번·고정 교직원 사번 기반 시연용 역할 분리와 역할별 동적 페이지 allowlist
- 학생 계정의 자기 체크인·결과 조회 범위 고정 및 로그아웃 시 session state 전체 삭제
- 학생별 1~4주 활동 800건과 4주차 체크인 200건, 대표 synthetic 학생 S0003의 별도 15주차 후속 관찰 1건
- 원본 데이터를 변경하지 않고 실제 존재 주차를 자동 표시하는 대시보드 조회 기준 주차와 주차별 실제 위험등급 기반 경보 후보 선정

- 가중 종합 위험도와 정상·관심·주의·고위험 등급

실제 학과·교과·비교과 파일은 활성화 전에 아래 명령으로 함께 점검합니다. 이 명령은 보고서만 출력하며 `data/` CSV, SQLite, 설정 파일을 생성하거나 수정하지 않습니다. 개인정보 가능 열은 헤더만 확인하고 값은 읽지 않으며, 허용된 설명 열에 연락처 패턴이 섞이면 안전 후보에서 제거합니다.

```bash
python -m src.master_import_service \
  --departments ../3.*.xlsx \
  --courses ../2.*.xlsx \
  --programs ../1.*.xlsx
```

위 glob은 상위 폴더에 `1.`·`2.`·`3.`으로 시작하는 대상 파일이 각각 하나일 때 사용합니다. 같은 점검은 교직원 `시연 준비` 화면의 `실제 master 전환 사전 점검`에서도 세 파일을 업로드해 실행할 수 있습니다.

점검 후 `검토 완료 master 활성화`를 펼치면 학과 → 비교과 → 교과목 순서로 적용할 수 있습니다. 활성화 전 확인 체크가 필요하며 기존 활성 파일은 `data/master_backups/`에 복사됩니다. 학과는 중복·미확정 코드를 모두 제외한 안전 후보만 저장하고, 교과는 개설 여부·학년·학기·학점·설명·역량·직무·관심 분야가 모두 있으며 교직원이 선택한 항목만 저장합니다. 새 실제 master가 누락되거나 검증에 실패하면 Repository는 `support_programs.csv` 또는 `courses.csv`를 자동으로 사용합니다.

2026년 개설강좌 파일은 다음 명령으로 별도 연결 점검합니다. 학생 대상 5개 학과와 관계없이 전 학과 강좌를 읽고, 학기·개설학과·교과목이 같은 분반을 통합한 뒤 전체 교과목 master와 연결합니다. CLI는 보고서만 출력하고 추천용 CSV나 SQLite를 바꾸지 않습니다.

```bash
python -m src.course_offering_import_service \
  --courses "../2. 전체 교과목.xlsx" \
  --semester-1 "../26년1학기 개설강좌.xlsx" \
  --semester-2 "../26년2학기 개설강좌.xlsx" \
  --year 2026
```

같은 점검은 교직원 `시연 준비`의 `2026 전 학과 개설강좌 연결 점검`에서도 실행할 수 있습니다. 학과가 5개 대상에 해당하는지는 `is_target_department`로 별도 표시할 뿐 추천 후보 원본에서 제외하지 않습니다. 현재 앱은 공식 과목코드로 중복을 제거한 987개 후보를 `courses_reviewed.csv`로 활성화해 사용합니다. 원본이 갱신되면 `실제 개설강좌 추천 master 활성화`로 다시 검증·전환할 수 있으며, 원본 Excel은 수정하지 않고 기존 활성 파일을 먼저 백업합니다.

## 발표 전 준비와 시연 원칙

`09 시연 준비`는 **발표 전에만** 사용합니다. 첫 화면에는 synthetic 1~4주 위험 흐름, Gemini 연결, SQLite 기록, 학생 시연 계정 `S0003`의 준비 상태와 대시보드 시작 버튼만 표시합니다. 실제 master 점검과 SQLite 초기화는 `고급 준비 도구`를 켰을 때만 나타납니다. 대시보드의 `조회 기준 주차`는 시연 여부와 관계없이 실제 스냅샷에 존재하는 주차를 표시하며 기본값은 최신 주차입니다. 선택 주차까지의 학생별 최신 자료만 조회하고 원본 CSV·SQLite·시스템 시간은 바꾸지 않습니다. 주차는 위험단계가 아니며 어느 주차든 해당 관찰 데이터가 기준을 넘으면 고위험 경보 후보가 될 수 있습니다.

발표가 시작되면 `시연 준비`를 닫고 일반 메뉴만 직접 사용합니다. 권장하는 서비스 흐름은 다음과 같으며, 앱이 이 순서를 강제하거나 답변을 자동 입력하지는 않습니다.

1. `전체 대시보드`의 `조회 기준 주차`에서 `1주차`부터 `4주차`까지 선택해 주차별 실제 위험등급을 확인. S0003은 데이터 결과상 관심→관심→주의→고위험으로 변화
2. 최신 4주차의 고위험 경보 후보에서 `학생 안내 보내기`를 펼쳐 내용을 확인하고 `시연용 안내 발송`을 누른 뒤 해당 synthetic 학생 계정으로 전환. 과거 주차는 조회 전용이며 실제 이메일 주소나 외부 메일은 사용하지 않음
3. `나의 체크인`의 학교 알림에서 `Kare와 이야기하기`를 누른 뒤 synthetic 학생의 짧고 자연스러운 말을 직접 입력. 한 문장의 여러 영역 이해·직접 근거·제출 전 확인·수정을 보여준 뒤 제출하여 `체크인 완료` 상태를 연결
4. 교직원 계정의 `학생 종합 확인`에서 주차별 추세·영역별 신호·학생 자유서술·상담 희망 확인
5. `AI 맞춤 추천 통합 검토`에서 학생이 확인한 AI 이해, DB 비교과 Top 3, DB 교과목 3~4개 학습경로와 근거를 함께 확인하고 승인·조정 필요·보류
6. `학생지원 진행 관리`에서 실제 지원할 비교과 프로그램·담당자·연락 예정일·다음 조치 확정
7. 같은 화면에서 대표 학생 S0003의 학생지원 상태를 `상담 완료`로 변경
8. `지원 후 변화 확인`에서 지원 시작 4주차와 synthetic 15주차 관찰의 종합·영역별 변화를 비교
9. 시간이 있으면 `신규 마이크로디그리 개발 후보`에서 수요순으로 정리된 반복 과목 조합과 교육과정 개발 근거 확인

`AI 맞춤형 학습 경로`는 개인 학생 지원이고, `신규 마이크로디그리 개발 후보`는 익명화된 다수 수요의 교육과정 환류입니다. 기본 대시보드의 1~4주 원본에는 미래 데이터를 섞지 않습니다. 대신 대표 학생 S0003이 `상담 완료`·`프로그램 참여`·`추후 관찰` 상태가 된 뒤에만 별도 `demo_followup_observations.csv`의 15주차 관찰을 `지원 후 변화 확인`에 연결합니다. 같은 학생에게 실제 15주차 이상 데이터가 있으면 synthetic 값은 적용하지 않습니다.

학생 `마이페이지`에서는 확정된 지원계획과 담당자·연락 예정일을 언제든 다시 확인할 수 있습니다.

시연 기록 초기화는 `시연 기록 초기화` 확인 문구와 동의 체크가 모두 있어야 실행됩니다. 초기화 직전 DB는 `database/backups/`에 자동 백업되며, synthetic CSV는 삭제하지 않습니다. 실제 대학 DB를 연결하는 운영 환경에서는 `config/app_config.yaml`의 `demo.enabled`를 `false`로 설정해야 합니다.

## AI 분석 및 추천 원칙

- Gemini는 자유서술·학습경로·교육과정 후보와 표준 다음 조치의 근거를 설명합니다.
- 학생이 동의한 Kare 대화에서는 Gemini가 전공 흥미·만족·지속 의향, 학습 어려움, 진로 명확성, 상담 필요, 관심 분야, 희망 직무, 고민의 9개 영역을 맥락으로 이해합니다. 한 발화에서 여러 영역을 찾을 수 있으며 학생의 실제 표현을 근거로 함께 저장합니다.
- Kare의 9개 영역은 학생에게 순서대로 묻는 설문이 아니라 내부 관찰 기준입니다. 별도 대화 계획기가 현재 이야기 줄기와 질문 의도를 선택하고, Gemini/Mock은 짧은 사실 반영과 질문 하나로 표현합니다. 페르소나 프롬프트는 학생이 말하지 않은 감정·빈도·원인을 만들지 않도록 제한하며, 다중 정보·모호함·없음·정정·선택지 요청·종료 요청 예시 중 현재 발화와 관련된 3개만 Gemini에 전송합니다.
- 관리자 검증 화면의 15개 대화 기준선은 Mock fallback과 결정적 서비스 제어의 회귀검증입니다. 실제 Gemini 확인은 선택 사례 한 건의 버튼을 눌렀을 때만 실행하며, 해당 사례의 학생 발화 수만큼 API를 호출합니다.
- Kare는 1~5 점수를 묻거나 추정하지 않습니다. 학생이 숫자를 말하더라도 대화의 정성 의미와 분리해 다루며, 의미 상태를 기존 숫자 위험변수로 변환하지 않습니다.
- 대화는 고정 턴 수나 9개 완성이 아니라 현재 어려움·관심 또는 강점·원하는 지원이 추천에 충분한지를 기준으로 최대 8턴 안에서 끝납니다. 질문 의도를 세션에 기억해 같은 말을 반복하지 않고, 근거가 부족한 영역은 `아직 판단하기 어려움`으로 남깁니다.
- 자연어 체크인은 지원 추천·학습경로·교직원 검토에 사용하며, 빈 척도를 중립점수로 대체하거나 기존 위험점수·주차를 변경하지 않습니다.
- 대화 요청에는 학생 ID·학번·성명을 넣지 않고 최근 대화만 사용합니다. 비동의 학생은 외부 전송 없는 직접 입력과 로컬 규칙 분석으로 같은 지원 흐름을 이용합니다.
- 현재 MVP의 AI 전송 동의 상태는 브라우저 세션에서만 유지하며 위험점수·지원 우선순위·추천 점수에 사용하지 않습니다. 실제 운영에서는 개인정보 검토를 거쳐 고지문 버전·동의/철회 시각만 별도 감사 로그로 관리해야 합니다.
- 학생이 제출 전에 확인한 자유서술 AI 분석을 저장 단계에서 재사용하여 같은 체크인의 중복 호출을 막습니다.
- 다음 조치는 설정에 존재하는 표준 행동만 허용하고, 담당자가 검토·수정해 저장하기 전에는 상태를 변경하지 않습니다.
- JSON parsing 후 애플리케이션에서 다시 JSON Schema validation을 수행합니다.
- 파싱·스키마·API 오류가 발생하면 검증된 Mock 분석으로 fallback합니다.
- Gemini의 원문 응답은 UI에 표시하지 않습니다.
- 프로그램 후보와 순위는 deterministic 코드가 `support_programs.csv`에 존재하는 ID만 대상으로 계산합니다.
- 추천 기본 가중치는 위험유형 일치 55%, 의미 유사도 30%, 지원수요 일치 15%이며 `config/app_config.yaml`에서 변경할 수 있습니다. 화면에는 각 프로그램별 위험영역·학생 서술·지원수요의 실제 일치 정도를 분리해 표시합니다.
- 교과목은 시스템 보유자료 기준 수강 필터를 먼저 통과한 후보만 사용하고 소속 학과·관심분야·희망직무·필요역량·학생 서술 유사도를 과목별 선정 근거로 표시합니다.
- 통합 승인·조정 필요·보류 결과는 같은 `source_checkin_id`의 비교과 추천과 저장된 교과 학습경로에 함께 기록됩니다. `조정 필요`는 교직원의 수정 사유를 저장하는 검토 상태이며 추천을 자동 재생성하지 않습니다. 학습경로가 없는 체크인은 비교과 검토만 저장했다고 화면에 명시합니다.
- 검토 결과, 확정 지원계획, 프로그램별 실행 상태는 `database/app.db`에 저장되며, 이 파일은 개인정보·운영기록 보호를 위해 Git에 포함하지 않습니다.
- 새 개입은 추천 생성 당시의 위험점수·등급·유형을 `risk_snapshots`에 고정 저장하고 `interventions.risk_snapshot_id`로 연결합니다.
- 학생이 직접 제출한 체크인과 검증된 AI 구조화 결과도 `database/app.db`에 저장되며, 학생 `마이페이지`와 교직원 `학생 종합 확인` 화면에서 확인할 수 있습니다.
- 학생 제출 시 생성한 프로그램 추천과 학습경로는 `source_checkin_id`로 연결되며, 교직원 화면은 같은 결과를 불러오므로 Gemini 호출과 추천·개입 기록을 중복 생성하지 않습니다.
- 교직원 화면의 생성 버튼은 저장 결과가 없는 기존 가상 체크인 또는 누락 결과 복구에만 표시됩니다. 새 분석이 필요하면 학생이 새 체크인을 제출해 별도 `checkin_id`로 이력을 남깁니다.
- 개입 상태와 허용할 학생 피드백 유형은 `config/app_config.yaml`에서 변경할 수 있습니다.
- 대시보드에서 미개입으로 볼 상태와 최대 표시 수 역시 `config/app_config.yaml`의 `dashboard`에서 변경할 수 있습니다.
- 의미 태그가 있는 기존 교과목 추천은 의미 유사도 40%, 관심분야 20%, 희망직무 15%, 역량보완 15%, 수강가능성 10%를 사용합니다. 실제 개설강좌처럼 태그가 없는 후보는 존재하는 과목명·개설학과·교과구분·NCS·학년·학점·수업방식 성분만으로 가중치를 재정규화하며, 없는 태그를 0점 근거로 만들거나 새로 생성하지 않습니다.
- Gemini는 코드가 선정한 교과목을 추가·삭제·교체할 수 없으며 반환 ID를 다시 검증합니다.
- 개발 후보의 학생·학과·교과목·역량 조건은 deterministic 코드가 결정하며 Gemini는 이를 공식 과정으로 확정할 수 없습니다.
- 교육과정 개발 후보가 여러 개여도 Gemini 설명은 한 번의 구조화 묶음 요청으로 생성합니다. HTTP 429 등 API 오류가 발생하면 코드로 확정한 후보와 수요 근거는 유지하고 설명만 Mock으로 전환합니다.
- 후보는 4과목 경로 전체가 같을 필요 없이 교과목 2개 이상이 반복되면 집계합니다. 3명 이상·2개 학과 이상의 다학과 수요 또는 한 학과 5명 이상의 특화 수요를 모두 후보로 표시하며, 기준은 `config/app_config.yaml`에서 변경할 수 있습니다.
- Sentence-Transformers 패키지 또는 로컬 모델을 사용할 수 없으면 UI에 안내하고 TF-IDF로 전환합니다. 네트워크를 통한 모델 다운로드를 허용하려면 `local_files_only` 설정을 변경해야 합니다.

## 데이터와 해석의 한계

- 가상데이터는 실제 학생 성과에 대한 예측 정확도를 입증하지 않습니다.
- 현재 역할 확인은 비밀번호 없는 synthetic 시연 계정용이며 실제 접근통제가 아닙니다. 운영 전환 전 대학 SSO·서버 세션·감사 로그 연동이 필요합니다.
- 학교 안내는 `demo_alert_notifications`에 시연 상태만 저장하며 실제 이메일 주소·이름·외부 메일 API를 사용하지 않습니다. 운영 전환 시 발송 동의·템플릿·감사 로그·재발송 정책이 필요합니다.
- 기본 가상데이터는 1~4주 활동과 4주차 체크인을 사용합니다. 대시보드의 조회 기준 주차는 실제 존재하는 주차만 표시하고 선택 주차까지 보이는 스냅샷 범위만 제한하며 원본이나 위험점수를 수정하지 않습니다. 해당 주차 입력이 없는 학생은 직전 자료를 사용했다는 인원 집계를 표시하고, 과거 주차에서는 안내를 발송할 수 없습니다. `demo_followup_observations.csv`는 S0003 한 명의 고정 synthetic 15주차 관찰이며 지원 완료 상태에서만 별도로 적용됩니다. 실제 15주차 이상 데이터가 존재하면 실제 데이터를 우선합니다.
- 성별, 연령, 국적, 장애, 경제상태, 건강정보, 종교, 정치성향은 생성하거나 위험점수에 사용하지 않습니다.
- 구조화 결과는 지원 우선순위 판단을 돕는 참고정보이며 학생의 최종 위험판정을 대체하지 않습니다.
- 현재 `support_programs_wings.csv`는 실제 Excel의 `비교과` 형식 102행을 운영 상태와 무관하게 포함합니다. `source_status`는 추적용일 뿐 추천 자격이나 순위에 사용하지 않으므로, 마감·게시 여부와 신청 일정은 WINGS에서 최종 확인해야 합니다.
- synthetic 12개 프로그램은 WINGS master가 없을 때의 fallback으로만 유지됩니다.
- 현재 `departments_master.csv`는 중복 학과명 2행과 미확정 코드 `???` 2행을 제외한 실제 학과 안전 후보 46개입니다. 학생 시연 모집단은 설정의 5개 학과로 유지합니다.
- 현재 `courses_reviewed.csv`는 2026년 1·2학기 개설강좌를 987개 고유 공식 교과목 후보로 변환해 활성화한 결과입니다. 전체 교과목 master와 연결되지 않은 후보 105개가 있고, 대부분의 강의개요·학습목표·역량·직무 태그와 실제 선수·학생 이수내역은 여전히 부족합니다. 화면은 이를 `확인 필요`로 표시하며 40개 synthetic 교과목은 활성 master가 없거나 손상된 경우의 fallback으로 유지합니다.
- 현재 강좌기본정보에는 공식 `교과목코드` 대신 개별 `강좌구분번호`가 있으므로 코드 연결에는 사용하지 않습니다. 설명 연결은 과목명·학과의 단일 일치만 자동 적용하며, 충돌하거나 일치하지 않는 과목은 기존 설명을 유지합니다. 과거 개설 이력은 현재 수강 가능 여부의 근거로 사용하지 않습니다.
- 스냅샷 기능 도입 전에 생성된 기존 개입은 당시 위험 결과를 소급 복원하지 않습니다. 새 개입부터 스냅샷이 연결됩니다.
- `지원 후 변화 확인`의 점수 증감은 후속 관찰을 위한 연관 지표이며 인과효과를 입증하지 않습니다. 위험점수 설정이 바뀌면 동일한 기준으로 재산출한 후 비교해야 합니다.
- synthetic 15주차 개선은 시연 흐름을 완결하기 위한 고정 사례이며 지원 효과나 실제 학생 성과의 증거가 아닙니다. 운영 환경에서는 실제 출결·LMS·성취·후속 체크인을 같은 규칙으로 계산해 대체해야 합니다.
- Kare synthetic 대화 15개는 개인정보 없는 개발용 참조 사례이며 실제 학생 표현의 분포나 Gemini의 운영 정확도를 입증하지 않습니다. 운영 전에는 학생 동의와 교직원 검토를 거친 비식별 참조 데이터로 같은 지표를 다시 측정해야 합니다.

## 향후 구현 예정

개발 명세의 핵심 흐름, 역할 분리, 5개 적용 학과 설정, 실제 WINGS 비교과, 통합 추천 검토, 수요순 마이크로디그리 개발 후보, 1~4주 조기경보와 Kare 연결, 실제 master dry-run·선택 활성화·자동 fallback이 구현되었습니다. 2026년 전 학과 개설강좌도 실제 필드만 사용하는 추천 후보 변환, 과거 강좌설명 안전 보강, 소속 학과 최소 2개·타과 최대 2개 구성, 과다 노출 제한, 반복 과목 조합 기반 마이크로디그리 후보와 확인 필요 표시까지 구현되었습니다. 지원 완료 뒤 S0003의 별도 synthetic 15주차 관찰을 연결하는 시연 경로도 구현되었습니다. 다음 작업은 `지원 후 변화 확인`에 안내 발송·Kare 체크인·추천 검토·지원계획·상담 완료 이력을 시간순으로 연결하고, 실제 선수과목 정보가 확보되면 수강 가능성과 설명 근거를 높이는 것입니다.
